# gorilla-bot

Автоматизация Telegram-бота «Gorilla» (казино, сейфы, питомец, бизнес, гонки,
бонусы) плюс рабочее окно на gpui-kit и собственный WSS-туннель до Telegram.

## Запуск

```cmd
gorilla-bot.exe            :: окно
gorilla-bot.exe check      :: проверка канала связи (ключ авторизации DC2)
gorilla-bot.exe login      :: вход по номеру телефона
```

Настройки лежат в `config.json` рядом с исполняемым файлом; образец —
`config.example.json`.

## Канал связи

Telegram доступен либо через локальный MTProto-прокси (SOCKS5), либо через
Cloudflare-прокси пула `kws*.{домен}` из репозитория
[Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy), поднятый как
локальный SOCKS5-мост (`127.0.0.1:8444`).

Список доменов бот берёт из репозитория при старте и обновляет раз в час
(`raw.githubusercontent.com/Flowseal/tg-ws-proxy/main/.github/cfproxy-domains.txt`),
свой список можно задать в `mtproxy.cf_domains`.

### Балансировщик

Домен для DC выбирается по замеру, а не по порядку в списке:

* каждое рукопожатие WSS замеряется, для пары «DC + домен» ведётся
  экспоненциально сглаженная задержка (EWMA, коэффициент 0.3);
* неудачное рукопожатие штрафует счёт (`(счёт.max(20)) × 2.5`, не больше 120),
  поэтому один отказ весит больше любой удачной задержки;
* замер живёт `score_ttl` секунд, дальше домен считается незамеренным и идёт
  после проверенных;
* если у домена уже есть свежий замер, он пробуется ОДИН и первым —
  измеренный лидер реально определяет выбор; забег включается только
  после его промаха;
* в забеге домены идут параллельно: по `probe_parallel` штук на пачку,
  побеждает самый быстрый, остальным даётся 0.5 с, чтобы их задержка тоже
  попала в счёт;
* таймаут одного рукопожатия — 15 с; весь пул идёт одной пачкой, поэтому
  мёртвый пул стоит одного таймаута, а не двадцати (пачки идут параллельно);
* готовые туннели держатся тёплыми: `pool_size` на DC, проверка каждые 5 с,
  максимум 100 с на туннель, пересборка с экспоненциальным backoff.
* `check` перед таблицей делает по одному забегу на DC2 и DC4, чтобы
  показать реальные счёт и отказы (`Балансировщик (DC → домен, …)`);

Если ни один домен пула не ответил, бот идёт по запасным вариантам: свой
Cloudflare-worker из `mtproxy.worker`, затем локальный TgWsProxy, затем
прямое подключение.

### Ключи `mtproxy`

| ключ | по умолчанию | смысл |
| --- | --- | --- |
| `host`, `port` | `127.0.0.1`, `8444` | адрес локального MTProto-прокси |
| `secret` | `""` | секрет MTProto-прокси; `""` — выбирать маршрут автоматически |
| `worker` | `""` | свой Cloudflare-worker (`*.workers.dev`) |
| `cf_domains` | `[]` | свой список доменов пула вместо списка из репозитория |
| `pool_size` | `2` | сколько тёплых туннелей держать на один DC (`0` — греть не надо) |
| `probe_parallel` | `20` | сколько доменов пробовать одновременно |
| `score_ttl` | `600` | сколько секунд живёт замер задержки |

`gorilla-bot check` печатает маршрут, таблицу балансировщика
(«DC → домен, счёт в секундах») и причины отказа по каждому домену, если пул
не ответил.
